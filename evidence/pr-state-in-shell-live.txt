Findings:
- Every shell carries `pullRequests` (each with `url` and `snapshot.state`, lowercase `open`/`merged`/`closed`),
  `linkedPullRequest` (null on every thread seen) and `branchPullRequest` (no state). boss reads `pullRequests`
  and, if present, `linkedPullRequest` into the wake signature.
- T3's copy goes stale: #6-#9, #11, #12, #14-#16, #18, #21 and #22 are MERGED on GitHub but still `open` in the
  shell, each `syncedAt` just before the merge and never again. The merges T3 did catch (#17, #19, #20, #23-#25)
  were synced within seconds of the merge.
- So the shell alone misses a PR merged later on GitHub. boss therefore also asks GitHub on every poke (a claim,
  the owner's turn starting or ending) about tasks whose ledger shows an open PR, at most every 5 minutes per task.
- Running threads push `thread.updated` every few seconds with a fresh `updatedAt` (even when `itemCount` holds
  still while text streams), so `updatedAt` is the stall sweep's progress mark. `latestVisibleMessage` was null on
  every thread, so the stall line's "last:" tail comes from one T3 read when the stall is detected.
